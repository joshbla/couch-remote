# Updating Couch Remote

The app is signed with the self-signed "Couch Remote Local Signing" certificate from the login keychain (see the README's Build section). Its designated requirement is tied to that certificate, so rebuilding keeps macOS Accessibility approval. Do not switch back to ad-hoc signing (`codesign -s -`): an ad-hoc identity changes on every build, and replacing the installed app then invalidates Accessibility approval. In that state, controller input still reaches the app, but macOS blocks the generated mouse and keyboard events. If the build cannot find the certificate, stop and report it rather than signing another way.

The canonical installed location is `/Applications/Couch Remote.app`. Keep the installed app running while building, testing, committing, and pushing. Replace and restart it only as the final step. Afterward, verify `accessibility` is `true` in `$TMPDIR/couch-remote-status.json`; do not infer success from controller detection alone. The app rewrites that file only when a reported value changes.

If approval becomes stale (for example after the certificate is recreated), run `tccutil reset Accessibility local.josh.couchremote`, restart the app, and have the user re-enable Couch Remote in Privacy & Security > Accessibility. macOS requires that user action.

For controller detection failures, read `docs/controller-detection.md` before repeating diagnosis. Inspect `GameControllerConfigService` logs as well as `gamecontrollerd`. A matching profile on disk does not prove the running helper can load it. Verify the status snapshot is being updated by a live app process before using it as evidence. A confirmed stale-profile failure was repaired by restarting the configuration helper, then the controller daemon, and reopening the app; restarting the controller daemon alone did not resolve it. Future prevention work is tracked in root `TODO.md` and has not been implemented.
